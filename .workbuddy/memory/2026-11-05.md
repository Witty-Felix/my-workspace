## 更正与收尾（2026-11-06 上午）

- **前面「域名未注册」的判断是错的**。真实域名是 `324614917.xyz`（9 位数字）；用户和我一直查的 `3246146917.xyz`（10 位，多一个 6）在注册局从未存在。少/多一位数字，导致 NXDOMAIN + RDAP 404 + 面板"正常"三者看似矛盾。
- 教训：**先问权威服务器再下结论**。`nslookup -type=ns <域名> ns0.centralnic.net` 是唯一有判决权的；面板只显示"提交成功"。同时——用户口述的域名要逐字核对位数，必要时让他截图控制台而不是手打。
- 子域名已通：`https://my-workspace.324614917.xyz/` → CF（Let's Encrypt 边缘证书）→ 源站 gateway → workbench。根域 `324614917.xyz` 仍是 buddy，由 gateway 的默认 server 块兜住。
- **新坑：bind mount 单文件会换 inode**。用 `tar xzf` 覆盖挂载进容器的 `nginx.conf` 后，容器里读到的还是旧 inode，`nginx -t` 通过、`reload` 成功，但配置没变。改成挂载 `conf.d/` 目录解决；改单文件挂载必须 `docker compose up -d --force-recreate`。
