## 拖拽态「晚上那筐被挤压」定位 + 原型（未改产品代码）

- 现象：拖拽中某天任务偏多（如周二下午）时，下午的卡片压过「晚上」格，晚上那筐看不见。
- 根因（两层，缺一不可）：
  1. `.zone { flex:1 1 0 }` 且外层 `body.dragging .sheet{min-height:640px}` 定高 —— 三格恒 180px，与内容多少无关。
  2. `.zone` 未设 overflow，默认 `visible` —— 实测下午格 clientHeight 176 / scrollHeight 649，卡片照原尺寸画出去，直接盖在下一格上。
- 原型：`design/prototypes/zone-fit/`（build.js → `design/prototypes/zone-fit.html`），四个方案 A/B/C/D 可切，带实时量尺（纸高 / 下午格 / 晚上格 / 压到下一格张数 / 是否需滚）。
  - A 现状复现：周二下午 3 张卡 → 6 张压在下一格。
  - B 按内容分高（`flex:0 0 auto`，纸跟着最长列长）：0 张挤压，纸 640→716px 仍一屏。
  - C 纸高不变、三格均分、格内滚：0 张挤压但 6 张要滚。
  - D 纸高不变、按卡数加权分高、格内滚：周二下午 180→222px，3 张要滚。
- 产品代码未改动，等用户选方案。

## 落地（同日晚）：采纳 B + 空白格 96px

- 用户选 B（按内容分高），并要求空白时段任务板高度 +0.5 倍；两种实现里选了「甲」= 绝对下限 96px（否决「相对兄弟格 ×1.5」的乙）。
- 改动（3 文件，+50/−7）：
  - `app/public/app.js`：`zoneEl` 给空白格打 `empty`；`renderWeek`/`renderPhone` 给整列全空打 `all-empty`。
  - `app/public/style.css`：桌面 `body.dragging .zone{flex:0 0 auto}`、`.zone.empty{min-height:96px}`、`.stack.all-empty .zone{flex:1 1 0}`；手机 `.phone-list.dropping` 同规则同 96px；`.zone .card{flex:0 0 auto}` 防卡片被压扁。
  - `docs/adr/0006-drag-place.md`：新增「修订（2026-11-10）」。
- 关键认知（推翻原型期的诊断）：症状**不需要靠 `overflow` 裁剪**解决。`flex:0 0 auto` 让框自然包住内容，就没有画到框外的部分；原型期以为「必须同时裁剪」是错的，ADR 已按实际机制重写。
- 整列全空需单独处理 `all-empty`（回到均分撑满），否则三格各 96px 会在纸面下半截留一片死白。
- 两端一致的关键：空白格**同取 96px**。手机基础保底本来就是 96px，所以手机端数值与改动前相同（无退化）；桌面 64→96 = ×1.5。
- 自检：`check` / `smoke` / `smoke:drag` / `smoke:done` 全绿；静止态 DOM 基线零变化。
- 踩坑：用 Python 改这三份文件会把行尾写成 CRLF，`npm run check` 第 3 项会挂 —— 改完必须转回 LF。
