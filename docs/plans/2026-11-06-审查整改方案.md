## Step 2 · 抽出共享领域模块 `app/lib/domain.js`（新增）

**修**：Primitive Obsession（时段三份）+ Duplicated Code ×2。

先说核对结论：**`server.js:49-55 bySortOrder` 与 `app/public/app.js:103-108 bySort` 逐行语义完全一致**（同样的 date 比较、同样的 `SLOTS.indexOf`、同样的 `(order||0)` 兜底），合并安全。唯一要注意的是 `indexOf` 对未知 slot 返回 `-1`（排在 `am` 之前）——两边行为本就相同，合并后不变。

`normalizeOrder`（server.js:57-68）与 `siblingsFn`（app.js:110-114）是同一形态的两份：**按 date+slot 分组 → 按 order 排序**。抽出 `groupKey` / `byOrder` 两个基元即可共用。

### 新文件骨架（UMD-lite，双端可用）

```js
/* 领域常量与排序规则：浏览器 <script> 与服务端 require 共用同一份
   —— 放在 lib/ 而非 public/，public/ 只留浏览器直接要的静态资源 */
(function (root, factory) {
  const api = factory();
  if (typeof module === 'object' && module.exports) module.exports = api;
  else root.WBDomain = api;
})(typeof globalThis !== 'undefined' ? globalThis : this, function () {
  'use strict';
  // 「时段」：只取上午/下午/晚上三值（GLOSSARY.md）
  const SLOTS = ['am', 'pm', 'eve'];
  const SLOT_LABELS = { am: '上午', pm: '下午', eve: '晚上' };

  // 分组键：同一天 + 同一时段 = 同组
  const groupKey = (a) => a.date + '|' + a.slot;
  // 组内顺序
  const byOrder = (a, b) => (a.order || 0) - (b.order || 0);
  // 全局顺序：日期 → 时段 → 组内顺序
  const compareArrangements = (a, b) => {
    if (a.date !== b.date) return a.date < b.date ? -1 : 1;
    const sa = SLOTS.indexOf(a.slot), sb = SLOTS.indexOf(b.slot);
    if (sa !== sb) return sa - sb;
    return byOrder(a, b);
  };

  return { SLOTS, SLOT_LABELS, groupKey, byOrder, compareArrangements };
});
```

检测顺序说明：浏览器 classic script 里 `module` 未定义 → `typeof module === 'object'` 为 false → 挂 `root.WBDomain`；Node CJS 里 `module.exports` 存在 → 走导出分支。`globalThis` 在 Node 12+ 与现代浏览器均可用，作为 `this` 的兜底。

## Step 3 · 抽存储层 `app/lib/store.js`

**修**：Duplicated Code / Speculative Generality（`{version, items}` ×6）+ Divergent Change（存储与路由分离）。

### 抽取时必须保持不变的隐式契约（这是最容易改坏的地方）

| 契约 | 现状 | 要求 |
|---|---|---|
| 缓存引用 | `load()` 每次返回**同一个对象引用**；PATCH 路由直接原地改 `db.items` 里的对象 | `load()` 必须返回缓存引用，不能返回深拷贝 |
| 原地变更 | PATCH 先改对象再 `save()`，即便 save 失败内存也已变 | 保持这个顺序与语义，不顺手"优化"成不可变 |
| 首次写入无 `.bak` | `save()` 里 `if (fs.existsSync(DATA_FILE))` 才复制备份 | 保留 |
| ENOENT 静默 | 文件不存在 → 空库，不报错；其他异常 → 打印「读取失败，按空库启动」 | 保留 |
| 原子替换 | 写 `data.json.tmp` → `rename` 覆盖；旧文件先复制成 `data.json.bak` | 保留 |
| **磁盘格式** | 固定写 `{"version":1,"items":[...]}` | **绝不能变**——这是回滚安全的唯一依据 |

### store.js 职责

```js
// app/lib/store.js —— 只管一件事：安排数据怎么落盘、怎么读回
'use strict';
const fs = require('fs');
const path = require('path');

const DATA_DIR = process.env.DATA_DIR || path.join(__dirname, '..', 'data');
const DATA_FILE = path.join(DATA_DIR, 'data.json');
const BAK_FILE = path.join(DATA_DIR, 'data.json.bak');
const CURRENT_VERSION = 1;          // 磁盘格式版本；改动必须 bump + 写迁移

let cache = null;

function envelope(items) { return { version: CURRENT_VERSION, items }; }

function load() {
  if (cache) return cache;                       // 同一引用，别破坏调用方的原地修改
  try {
    const parsed = JSON.parse(fs.readFileSync(DATA_FILE, 'utf8'));
    if (parsed.version > CURRENT_VERSION) {
      console.warn(`[store] 数据版本 ${parsed.version} 高于当前 ${CURRENT_VERSION}，按 v${CURRENT_VERSION} 读取`);
    }
    cache = envelope(Array.isArray(parsed.items) ? parsed.items : []);
  } catch (err) {
    if (err.code !== 'ENOENT') console.error('[store] 读取失败，按空库启动：', err.message);
    cache = envelope([]);
  }
  return cache;
}

function save(next) {
  fs.mkdirSync(DATA_DIR, { recursive: true });
  const tmp = DATA_FILE + '.tmp';
  fs.writeFileSync(tmp, JSON.stringify(next, null, 2), 'utf8');
  if (fs.existsSync(DATA_FILE)) fs.copyFileSync(DATA_FILE, BAK_FILE);
  fs.renameSync(tmp, DATA_FILE);
  cache = next;
}

module.exports = { DATA_FILE, BAK_FILE, load, save, envelope, CURRENT_VERSION };
```

`version` 字段第一次有了用途：`load()` 会校验并在版本超前时告警。**写出仍固定 v1**，`items` 字段名不动。
