# 完成：卡片右上角一个常驻勾，只改外观不改排序

「做完了」需要一个落点。用户的实际流程是：学生临时请假就把卡拖到下一个约好的时间——那是改期，不是完成；只有真做完了才划掉。所以完成只做一种状态，不做「作废 / 取消」，也不该和拖拽抢手势。

## 决定

- **状态只有一个，存储是稀疏的 `doneAt`**（ISO 时间戳）。完成时写入，取消时删掉字段，不写 `done:false`。老数据没有这个字段，读出来就是未完成，不需要迁移，`store.js` 版本仍是 1。
- **接口走已有的 `PATCH /api/items/:id`**，新增 `done: true|false`；非布尔返回 400。重复完成保持第一次的时间戳（幂等）。
- **勾常驻右上角**，19px 方框、31px 命中区（伪元素撑），触屏也常显；`↑↓` 往左让 22px。点勾只改完成状态，不打开编辑框、不起拖。
- **完成态只改外观**：标题划线、备注与时段褪墨、投影收一档。不沉底、不收进「已完成」区，位置和顺序都不变。
- **完成不影响任何交互**：已完成的卡照样能拖、能改标题、能删、能再点一下取消。拖=改期，勾=记录，两件事正交。
- **乐观更新**：先改本地再 PATCH，失败 toast + `refresh()` 以服务端为准回滚；落位与完成共用一个写队列，连点两下不会乱序。
- **词与代码的对应**：领域词是「完成」（状态）和「划掉」（动作）；代码里的 `done` / `doneAt` 只是接口与存储的字段名，界面文案是「标记完成 / 取消完成」。

## Considered Options

- **复用时段圆点 `.sdot` 当勾选框**（原型里的 A 案）：能保住静止态 DOM，但线上手机端把整行 `.meta` 藏了，A 必须把这行请回来——每张卡多一行、时段标签与分组头重复；而且 12px 的方框在手机上太难点。放弃。
- **只放进编辑框**（C 案）：零基线代价，但「在板上划掉」变成两步，丢掉这个功能本来要的那一下确认感。放弃。
- **加一个「作废」状态**：完成是资产、作废是止损，用户的处理方式却是改期；一个布尔值混着两种结局会让周复盘失真。先不做，真需要时再加 `status` 并写迁移。
- **完成后沉到当天末尾**：`placeItem` 的插入位次是按眼前 DOM 顺序数的，按 done 重排会让「眼前第几位」和「数据里第几位」错位，拖拽当场失准。放弃。

## Consequences

- **静止态 DOM 变了**：每张卡多一个 `<button class="tick">`。这是 ADR-0006 之后第一次有意破基线：`SMOKE_ACCEPT=1 npm run smoke` 把差异写进 `app/scripts/dom-accepted.diff`（3 处、6 行），接口契约 19 条调用仍逐字一致（夹具没有 `doneAt`，响应里不会凭空多字段）。
- **CI 是拿 `HEAD~1` 比的**（`.github/workflows/check.yml`）。有了 `dom-accepted.diff`，单提交推送时 `HEAD~1` 算出的正是这份 diff，CI 认它；基线变更本身就在提交里可评审。以后再改静止态 DOM 或接口响应，同样 `SMOKE_ACCEPT=1 npm run smoke` 更新对应文件。
- **卡片内多了可聚焦控件**：勾是原生 `<button>`，Tab 能到、Enter/Space 能按。卡片自己的 keydown 改成只认 `e.target === card`，顺带修掉了「在 ↑↓ 上按 Enter 会同时打开编辑框」。
- **拖影里摘掉勾**：`startDrag` 克隆卡片时把 `.acts` 和 `.tick` 一起移除；`pointerdown` 也把 `.tick` 排除在起拖之外。
- 手机端右侧要腾位置：卡片右内边距 44 → 64px（单卡 34px），排序钮从 `right:0` 挪到 `right:27px`。这些只是 CSS，不影响 DOM 比对。
