# 助手：立方体入口 + 非模态聊天窗，模型只出草案、用户点了才写

用户想「把下周的规划发给它，它帮我写进工作台；把今天的任务发给它，它帮我编到对应日期上」。这是这个仓库第一次让模型参与写入，所以边界比功能本身重要：**模型可以猜，但不能直接落库。**

## 决定

- **入口是右下角一枚立方体**（Uiverse / Juanes200122 / light-lion-95，3D 立方体旋转）。它在纸外，所以桌面只在 ≥901px 出现。点的动作只有开/关窗口，没有第二个功能。
- **手机入口在 `.bar` 里，不在 `.nav` 里**。`.nav` 在 ≤900px 是 `display:none`，入口放进去等于手机上不存在 —— 这是本仓库最常漏的一项（见 `AGENTS.md`「两端一起做」）。`.bar` 在 ≤620px 会换行并给子项排 `order`，新按钮必须显式 `order:2` 且把 `margin-left:auto` 让给开关，否则会掉到最左边压住品牌。
- **聊天窗不是 `<dialog>.showModal()`**。模态弹框进原生 top layer，会吃掉整页点击，而这里的用法是「一边看纸上的条目，一边确认要写什么」。所以是普通 `position:fixed` 浮层（`z-index:70`，高于规划窗的 `60`），桌面可拖、无暗罩；手机换成贴底抽屉 + 暗罩。
- **新增 `POST /api/chat`，只读**。它调一次 OpenAI 兼容接口，返回 `{ reply, draft, dropped, model }`，**不碰 `data.json`**。密钥只在服务端（`AI_KEY`），浏览器拿不到；上游报错正文不回给前端（可能带 key 片段与内网地址）。
- **草案由服务端逐条校验，不信模型**：日期必须真实且落在今天前后 120 天内、`slot` 必须是 `am/pm/eve` 白名单、标题非空且截断到 80 字。被丢掉的条目计数回前端，在回执里说清楚，不静默吞掉。
- **写入走已有的 REST 动词**（`POST /api/plan`、`POST /api/items`），不新开批量接口。理由：复用同一套校验；失败时能精确知道停在哪一条，而批量接口只会整单失败。写完 `refresh()` 按服务端重取，不在本地拼。
- **写完的草案变灰且不可再点**。中途失败时，已写成功的条数记账后清空剩余，避免用户再点一次写出重复。
- **跨周必须提示**。草案落在别的 ISO 周时，卡片底部标「落在 W47，不在这张纸上」并转琥珀色 —— 否则点完「写入」纸上毫无变化，会被当成没写成功。
- **字段名与词表的对应**（`CODING_STANDARDS.md`《数据》要求）：
  - `draft.items[]` ↔「安排」（同 `data.json` 的 `items`，字段完全一致：`date` / `slot` / `title` / `note`）
  - `draft.plans[]` ↔「规划条目」（同 `plans`：`week` / `title` / `note`）
  - `reply` ↔ 助手那一句回执，只作对话内容，不承载数据
  - `dropped` ↔ 被校验丢弃的条数，只用于告知
  - 界面上的窗口 ↔「助手」（不叫「AI 助手」，避免与词表里的其他词混）
- **磁盘格式与版本号都没动**。助手不产生新的存储形态，写进去的东西和手输的一模一样。
- **没有 `AI_KEY` 时 `/api/chat` 返回 503 并说明怎么配**，不静默降级成假数据。其余功能完全不受影响。

## Considered Options

- **让模型直接写库**（在 `/api/chat` 里落盘）：放弃。模型会编日期、编时段；写错要一条条删，比多看一眼贵得多。而且用户看不到它到底写了什么。
- **前端直连模型接口**：放弃。浏览器里的密钥等于公开。
- **批量写入接口**：放弃。失败语义差，且绕过了逐条的字段校验。
- **`<dialog>.showModal()`**：放弃。见上：这个窗口的用法要求页面仍可点。
- **让模型自己算日期**：放弃。改为把本周/下周/上周的日期表整张塞进系统提示词，让它查表而不是做算术。实测「下周三四」能稳定落到正确的 `YYYY-MM-DD`。
- **把模型回复当 HTML 渲染**：放弃。一律 `textContent`，草案当数据不当内容。

## 后果

- 需要配 `AI_KEY`（`app/.env` 或 `docker-compose.yml` 的 environment）。`AI_BASE` 默认 `https://api.deepseek.com`，`AI_MODEL` 默认 `deepseek-chat`；换成任何 OpenAI 兼容端点都行。
- `POST /api/chat` 是唯一会花钱的路由。消息条数（20）、单条长度（2000）、草案条数（20）都在服务端截断。
- 静止态 DOM 多两个常驻节点：`.mchat-btn`（桌面 `display:none`）与 `.cube-entry`（窄屏 `display:none`）。基线变更见 `app/scripts/dom-accepted.diff`。
- 自检：`node scripts/smoke-chat.mjs`（无 `AI_KEY` 时只跑入口与窗口的 6 项；有 key 时跑满 11 项，含真实写入落库）。
- 模型选型是配置项，不是架构决定。换模型只需要改 `AI_MODEL`，提示词与校验层都不用动。
