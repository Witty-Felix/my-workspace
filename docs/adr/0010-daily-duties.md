# 每日必做：第三种内容单位，按天归属，两端不同形

用户每天固定做四件事（戒色 / 读书 / 离开整理桌面 / 每日一善），要一个每天看的清单。它与「安排」（挂周轴某天某时段）和「周规划」（挂某一整周）都不同：**只归属到某一天，四项固定，不增删、无标题编辑**。原型验证（`design/prototypes/daily-duties/`，已随会话丢弃）选定：桌面 B 抽屉、手机 A 抽层。

## 决定

- **一张独立表 `duties`**：记录形如 `{ day, key, doneAt }`——哪一天、哪一项（`jieSe|read|tidy|kind` 四值白名单）、何时完成。没有 `id`：`(day, key)` 天然唯一，upsert 按它定位。`store.envelope()` 增加第三个数组，磁盘上与 `plans` 同样稀疏（空了不落盘），版本号仍是 1，老数据读出来就是空。
- **「每日更新」是查询语义，不是删除**：取某天就按 `day` 过滤；今天没做的就是空。数据从不按天清空——本周点阵、连续天数这些要用的历史都靠它。`GET /api/duties?day=` 单日，`?from=&to=` 区间（点阵一次带回，不逐天发请求）。
- **勾选走 `PATCH /api/duties/:key`**（body: `{day, done}`）。幂等：重复完成保持第一次的 `doneAt`（同 ADR-0007 的语义）；取消就删记录。
- **envelope 调用点全改**：ADR-0008 的教训直接兑现——这次把 `store.envelope` 的 9 个调用点**全部**补上 `db.duties`，漏一个就会在保存安排/规划时把打卡记录整块抹掉。
- **两端刻意不同形**（CODING_STANDARDS《两端》给了两种合法选项，这里选「两端都写但不同形」）：
  - **桌面 = B 抽屉**：右侧全高，进度环（n/4）+ 每卡连续天数 + 本周点阵（周一→周日，今天落在自己那格）。理由：桌面屏幕大、停留久，看得见「轨迹」才有坚持的激励感；用自然周而不是滚动 7 天，是为了和周轴的「周」对齐——同一天在点阵里的位置固定，不会每天往左漂。
  - **「连续 N 天」是周内连续**：从今天那格往回数到周一为止（周一当天空就 0 天，打卡了就是 1 天），不跨周累计。口径与点阵一致，看得见的那几个点就是它的依据；要算跨周长连续得另存聚合，等真有需求再说。
  - **手机 = A 抽层**：底部升起，四行大勾选。理由：手机上是睡前快速过一遍的场景，要的是大字大命中区，点阵和环都是噪音。
  - 两套节点共享同一份 `dailyUi` 状态与同一条写队列；窄屏渲染抽层、桌面渲染抽屉，互不串场。
- **入口**：桌面顶栏「必做」标签（与「规划」并排）；手机顶栏「日」方块（`.bar` 里，窄屏 `.nav` 整条隐藏，理由同 `mChatBtn`；620 以下换行排号 `order:2`，理由同 ADR-0008）。四项全勾时入口点亮（金色 / ✓），给「今天已完成」一个不用点开就能看到的状态。
- **窗口只在打开时渲染**，宿主 `#dailyHost` 平时是空 div（同规划窗的思路，静止态 DOM 只多 3 个节点：`#dailyBtn`、`#mDailyBtn`、`#dailyHost`）。
- **勾选只刷外观不重建**：`paintDaily()` 改既有节点的类名/文本/点阵，不重画容器——按下与松手之间不许重建节点（CODING_STANDARDS《界面》）。重建只在开/关与跨天时发生，且重建前先清宿主（原型期「越勾越黑」的教训：appendChild 叠层）。
- **打开即拉数据，不画空窗**：`openDaily()` 先 `await loadDaily()` 再渲染一次成型。刷新后首开若先画空窗，数据回来再重画，等于闪一下「全部未完成」的假象。
- **跨天自愈**：开着抽屉过了午夜，30s 心跳发现日期变了就重拉。关着不用管——下次打开自然拉新的一天。

## Considered Options

- **复用 `plans` 表加 `kind: 'daily'`**：规划与必做语义完全不同（周 vs 天、可增删 vs 固定四项），混一张表则每个查询都要带 kind 过滤，漏一处就把必做画进周规划。放弃。
- **桌面也用原型 A（浮窗）**：省一套样式，但浮窗遮挡周轴且与规划窗争「右下角」；抽屉不遮纸、能边看周轴边勾。放弃。
- **手机复用桌面抽屉**：390px 装不下 392px 抽屉，且点阵/环在手机上是噪音。放弃。
- **隔日清零写成删除任务**（每天凌晨把昨天的记录删掉）：丢历史，点阵无从谈起。放弃。
- **四项做成可配置**：原型阶段用户明确「固定四项」，配置界面是还没被需要的复杂度。key 写死在前后端共用处，真要配置时再迁移。

## Consequences

- **DOM 基线变更 `+3 / -0`**：`#dailyBtn`、`#mDailyBtn`、`#dailyHost` 三个常驻节点。`SMOKE_ACCEPT=1` 重新接受了基线（`dom-accepted.diff` 随本提交）。
- **`GET /api/duties` 有两种参数形态**（day / from+to），校验分别做；`day` 与 `from/to` 都不传是 400。
- **新增自检 `npm run smoke:daily`**（23 项）：桌面开合/勾选/落盘/刷新读回/取消/Esc、手机入口可见性/形态隔离/勾选落盘、隔日清零语义、全程无 JS 异常。写它的过程中抓出两个真 bug：服务端漏了区间查询（前端 `?from&to` 打到 400）、`renderDaily` 漏调 `paintDaily`（刷新后打开全是未完成外观——原型靠全量重画掩盖，正式版只搭骨架就露馅）。
- **harness 的 dbg 探测顺带修了**：上次运行残留的 `DevToolsActivePort` 指向死端口会让所有自检偶发「拿不到页面调试目标」；现在读到端口先探活。这个 bug 在 HEAD 上就有，不是本次引入。
- **词表新增**：「每日必做 / 必做条目 / 必做抽屉」三条；代码里 `duties` / `DUTIES` / `dd-*` 是它们的字段名与类名。
