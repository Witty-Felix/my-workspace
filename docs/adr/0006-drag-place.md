# 拖拽落位：落点即时段，松手先改界面再写服务端

原来调整顺序只有卡片右上角的 ↑↓，而它只认「同一天 + 同一时段」这一组：上午的卡挪不到下午，更挪不到别的天——想跨天跨段只能点开编辑框改时段。这次把排序换成拖拽，并定下一条核心规则：**落点决定时段，不存在「非法落点」**。拖起来时每一列（手机是当天列表）铺开上午/下午/晚上三格，落在哪格就归哪段；空白的日子三格照铺，随手一丢落在最上面的上午格，就是「默认上午」，不用再弹窗问。

拖拽用 Pointer Events 自己实现，没有用 HTML5 拖放：后者在触屏上不工作，且拖动期间拿不到实时改样式的句柄，做不了跟手的影子卡和贴边翻页。

## Considered Options

- **HTML5 拖放（dragstart/dragover/drop）**：代码少，但无触屏支持，拖影是浏览器快照，贴边自动翻页这种需要「拖拽中持续改界面」的动作做不了。
- **永久把每列改成三段**：落点最直观，但静止态 DOM 与视觉全变，`scripts/smoke.sh` 的逐字渲染比对要重建基线，而且七列窄栏常年挂着三个空格子，视觉噪音太大。选择只在拖拽期间铺开。
- **服务端强制同时段**：等于把界面限制升级成数据规则，但「拖到下午」本身是合法操作（编辑框早就能改时段），禁止它只会让落位接口变成半个编辑接口。服务端只校验形状，时段策略交给落点。

## Consequences

- **静止态 DOM 零改动**：投放格只在拖拽时生成，`npm run smoke` 拿旧基线比对仍然逐字一致；`↑↓` 的手绘箭头也只用 CSS 伪元素换字形，文字节点留着给读屏软件。
- **新增 `POST /api/items/:id/place`**（`date` / `slot` / `index`），服务端调用与浏览器同一份 `lib/domain.js` 的 `placeItem`，两边排序算法不会漂移。旧的 `/move` 保留，键盘与按钮仍走它。
- **松手先改界面再写服务端**：跨境往返一两秒，等确认再动就是卡死。失败时 `refresh()` 以服务端为准回滚。多次拖拽按顺序串行发送——后一次的 `index` 是照前一次改完的本地状态算的，乱序到达会让服务端顺序和眼前看到的不一样。
- **贴边连拍**：贴住边缘 0.6 秒翻第一页，之后每 0.8 秒一页，恒定不加速；离开边缘立刻停拍，重新贴边从头计。指针滑出窗口或窗口失焦也停，避免看不见的时候一直翻。边缘只做导航，松手不落位。
- **拖拽中翻周不走忙碌态**：`body.busy` 会给 `.stage` 加 `pointer-events:none`，那会让落点判定全部失效，所以 `shiftWeek(n, quiet)` 有静默档。
- 翻周/翻天用的是起手预取的前后两周数据，一次性、写操作后清空；翻得更远仍会等一次网络。

## 修订（2026-11-09）：投放格改成覆盖层，指针捕获挪到 body

上线后在真机上测出三件原方案没覆盖到的事，改了两处实现，决策本身（落点即时段）不变：

- **不再重排列表铺三格**。原方案在起手时 `render()` 把这一天重画成三个格子，纸会长高约 60px、整页跟着跳；更要命的是触屏指针默认捕获在被重画掉的卡片上，卡片一消失浏览器就释放捕获并派发 `pointercancel`，拖拽当场结束——鼠标没有这层捕获，所以桌面一直是好的。现在改成一层 `position:fixed` 的覆盖层：格子按原卡片的上下沿算出来，卡片留在原位半透明，列表不重排，纸不长高。
- **起手把指针捕获到 body**。翻周/翻天仍会重建卡片，捕获挂在不会消失的节点上，重建之后照样跟手。
- **触屏改成按住 250ms 才算拿起**，待命期间允许 10px 抖动；拿起之后由 `touchmove` 的 `preventDefault` 接管滚动。没长按就滑动的仍然是滚页面。

代价：一天只剩一条安排时，三个格子只能挤在纸面下半段（命中区不小于 24px，地方不够就盖到纸外）。换来的是拖拽期间零重排。原来那条「纸会长高 60px」的已知代价随之作废。

配套：`scripts/smoke-drag.mjs` 增加触屏档（移动视口 + `Input.dispatchTouchEvent`）。原先它只发鼠标事件，所以「鼠标能拖」一直被当成「能拖」。

实现：`public/app.js` 的「拖拽落位」段（`bandsFor` / `buildZones` / `hitTest` / `startDrag`）；自检：`npm run smoke:drag`（鼠标档 + 触屏档）。
