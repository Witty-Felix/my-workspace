# 拖拽落位：落点即时段，松手先改界面再写服务端

原来调整顺序只有卡片右上角的 ↑↓，而它只认「同一天 + 同一时段」这一组：上午的卡挪不到下午，更挪不到别的天——想跨天跨段只能点开编辑框改时段。这次把排序换成拖拽，并定下一条核心规则：**落点决定时段，不存在「非法落点」**。拖起来时每一列（手机是当天列表）铺开上午/下午/晚上三格，落在哪格就归哪段；空白的日子三格照铺，随手一丢落在最上面的上午格，就是「默认上午」，不用再弹窗问。

拖拽用 Pointer Events 自己实现，没有用 HTML5 拖放：后者在触屏上不工作，且拖动期间拿不到实时改样式的句柄，做不了跟手的影子卡和贴边翻页。

## Considered Options

- **HTML5 拖放（dragstart/dragover/drop）**：代码少，但无触屏支持，拖影是浏览器快照，贴边自动翻页这种需要「拖拽中持续改界面」的动作做不了。
- **永久把每列改成三段**：落点最直观，但静止态 DOM 与视觉全变，`scripts/smoke.sh` 的逐字渲染比对要重建基线，而且七列窄栏常年挂着三个空格子，视觉噪音太大。选择只在拖拽期间铺开。
- **服务端强制同时段**：等于把界面限制升级成数据规则，但「拖到下午」本身是合法操作（编辑框早就能改时段），禁止它只会让落位接口变成半个编辑接口。服务端只校验形状，时段策略交给落点。

## Consequences

- **静止态 DOM 零改动**：投放格只在拖拽时生成，`npm run smoke` 拿旧基线比对仍然逐字一致；`↑↓` 的手绘箭头也只用 CSS 伪元素换字形，文字节点留着给读屏软件。
- **新增 `POST /api/items/:id/place`**（`date` / `slot` / `index`），服务端调用与浏览器同一份 `lib/domain.js` 的 `placeItem`，两边排序算法不会漂移。旧的 `/move` 保留，键盘与按钮仍走它。
- **松手先改界面再写服务端**：跨境往返一两秒，等确认再动就是卡死。失败时 `refresh()` 以服务端为准回滚。多次拖拽按顺序串行发送——后一次的 `index` 是照前一次改完的本地状态算的，乱序到达会让服务端顺序和眼前看到的不一样。
- **贴边连拍**：贴住边缘 0.6 秒翻第一页，之后每 0.8 秒一页，恒定不加速；离开边缘立刻停拍，重新贴边从头计。指针滑出窗口或窗口失焦也停，避免看不见的时候一直翻。边缘只做导航，松手不落位。
- **拖拽中翻周不走忙碌态**：`body.busy` 会给 `.stage` 加 `pointer-events:none`，那会让落点判定全部失效，所以 `shiftWeek(n, quiet)` 有静默档。
- 翻周/翻天用的是起手预取的前后两周数据，一次性、写操作后清空；翻得更远仍会等一次网络。

## 修订（2026-11-09）：投放格改成覆盖层，指针捕获挪到 body

上线后在真机上测出三件原方案没覆盖到的事，改了两处实现，决策本身（落点即时段）不变：

- **不再重排列表铺三格**。原方案在起手时 `render()` 把这一天重画成三个格子，纸会长高约 60px、整页跟着跳；更要命的是触屏指针默认捕获在被重画掉的卡片上，卡片一消失浏览器就释放捕获并派发 `pointercancel`，拖拽当场结束——鼠标没有这层捕获，所以桌面一直是好的。现在改成一层 `position:fixed` 的覆盖层：格子按原卡片的上下沿算出来，卡片留在原位半透明，列表不重排，纸不长高。
- **起手把指针捕获到 body**。翻周/翻天仍会重建卡片，捕获挂在不会消失的节点上，重建之后照样跟手。
- **触屏改成按住 250ms 才算拿起**，待命期间允许 10px 抖动；拿起之后由 `touchmove` 的 `preventDefault` 接管滚动。没长按就滑动的仍然是滚页面。

代价：一天只剩一条安排时，三个格子只能挤在纸面下半段（命中区不小于 24px，地方不够就盖到纸外）。换来的是拖拽期间零重排。原来那条「纸会长高 60px」的已知代价随之作废。

配套：`scripts/smoke-drag.mjs` 增加触屏档（移动视口 + `Input.dispatchTouchEvent`）。原先它只发鼠标事件，所以「鼠标能拖」一直被当成「能拖」。

实现：`public/app.js` 的「拖拽落位」段（`bandsFor` / `buildZones` / `hitTest` / `startDrag`）；自检：`npm run smoke:drag`（鼠标档 + 触屏档）。

## 修订（2026-11-09 晚）：投放格改回流内三格，触屏安全改由「固定锚点」保证

真机复测推翻了上一条修订的核心假设。上一版把 pointercancel 归因于「指针捕获位置」，于是改用覆盖层让列表零重排；但真机继续测出「拖到下一天突然消失」——真正的根因是：**触屏的 touch 序列绑定在 `pointerdown` 时的目标卡片节点上，任何时刻把该节点从 DOM 摘除（重建列表必然摘除它），浏览器都会派发 `pointercancel`**。覆盖层只是让「拖拽起点」不重建，可贴边翻天之后 `refresh()` 仍会重建列表，原卡照样被杀。`setPointerCapture(body)` 救不了它——捕获只改事件路由，不改 touch 目标的生死判定。

**解法：把「原卡不能死」和「列表要重排」解耦。** 拿起瞬间把原卡从列表摘出、挂到 `body` 直属的固定锚点（`.drag-anchor`，`visibility:hidden` 视觉全隐）；此后列表/翻页/翻天随便重建，touch 目标永生。锚点随 `endDrag` 删除，`render()` 按数据把卡画到新位置。

投放格同时改回流内三格（ADR 初版的方案）：拖拽态每天列/手机列表直接铺开上午/下午/晚上三个方框，卡片住自己时段的框，空档也留位——真机用户反馈覆盖层「按卡片上下沿」算出的格子与卡片错位（空档小格挤在卡片缝里）、格子太小、空天没格子。流内三格下：桌面拖拽态纸面拉高（`min-height:640px`）、手机当天列表撑满视口（`.phone-paper.stretch`），三格 `flex:1 1 0` 均分列高；静止态 DOM 仍然零改动，smoke 基线照旧逐字一致。

Consequences 变化：
- 「拖拽期间零重排」作废——拖拽态列表每次都重排，但重排不再威胁拖拽本身（原卡在锚点里）。
- 被拖的卡从渲染池排除：拖拽中它在列表里 0 次出现，唯一可见形态是跟手影子（防残影）。
- 覆盖层机器（`bandsFor`/`buildZones`/`zoneAt`/`zone-layer`/`.drag-src`）整体删除；格子高亮直接 `elementFromPoint` 命中流内 `.zone`。
- 「一天只剩一条安排时格子挤在纸面下半段」的代价作废——流内三格按列高均分，纸面拉高后每格 ≈180px。

实现：`public/app.js`「拖拽落位」段（`zoneEl`/`hitTest`/`startDrag`/`endDrag`）；自检：`npm run smoke:drag`（鼠标档 + 触屏档，选择器已随流内格子更新）。

## 修订（2026-11-10）：三格不再瓜分列高，空白时段另给高一档保底

真机上另一类投诉：**某天某时段安排一多，「晚上」那筐整个看不见**。量到的因是：`.zone{flex:1 1 0}` + `body.dragging .sheet{min-height:640px}` 让三格恒定均分列高（每格 ≈180px），格子高度与格内装了多少东西完全无关，而 `.zone` 的 `overflow` 默认 `visible` —— 实测周二下午格 `clientHeight 176` / `scrollHeight 649`，卡片按原尺寸画出去，直接盖在下一格上，「晚上」的标签与卡片被整块吃掉。

修法是让格子退出瓜分：`.zone` 与 `.stack` 在拖拽态都取 `flex:0 0 auto`，格子高度 = max(保底, 自己内容高)，框自然包住内容，不再有画到框外的部分，于是不依赖 `overflow` 裁剪。落位命中照样准——`elementFromPoint` 命中的始终是卡片真正所在的那个格子。

代价是纸面按最长的那列长高，内容特别多时整页要滚：桌面 1440×900 下，单格 8 条约 915px，整页需滚 ≈400px。

空白时段单独给高一档的保底，两端同取 96px（桌面基础保底 64×1.5；手机基础保底本来就是 96，取同值即为不额外加高）。理由同初版——空白的日子三格照铺，最上面那格是上午，空格是纯落点，要比卡片格更好丢。

**整列都没有安排时例外**：那一列没有对照组，三格各 96px 会让纸面下半截留一片死白，所以整列标记 `all-empty`、三格均分撑满列高。桌面与手机同一条规则。

Consequences 变化：
- 「三格 `flex:1 1 0` 均分列高」作废，改为按内容分高；只有整列全空时才回到均分撑满。原代价「一天只剩一条安排时格子挤在纸面下半段」随之作废。
- `.zone .card{flex:0 0 auto}`：卡片不参与压缩，避免格子变矮时卡片被挤扁（原型里有这行，主样式此前漏了）。
- 纸面高度不再固定 640px，随内容长；`body.dragging .sheet{min-height:640px}` 保留，配合 `all-empty` 兜空周的底。
- 静止态 DOM 不变（`empty` / `all-empty` 只在拖拽态生成），smoke 基线照旧逐字一致。
- 桌面与手机共用同一条规则，空白格保底同取 96px，两端观感一致。

实现：`public/app.js` 的 `zoneEl`（空白格打 `empty`）与 `renderWeek` / `renderPhone`（整列全空打 `all-empty`）；`public/style.css` 拖拽段落（桌面 media query 与 `.phone-list.dropping`）。
自检：`npm run smoke:drag`（鼠标档 + 触屏档）、`npm run smoke:done`。

实测（拖拽态，卡片越过自己格子下沿的张数）：

| 端 | 视口 | 有卡的列 · 空白格 | 有卡的列 · 塞满的格 | 整列全空 | 压到下一格 |
|---|---|---|---|---|---|
| 桌面 | 1440×905 | 96px | 427px（6 张） | 206px × 3 | 0 张 |
| 手机 | 390×844 | 96px | 298px（5 张） | — | 0 张 |
