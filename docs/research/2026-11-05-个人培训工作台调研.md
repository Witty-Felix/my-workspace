## 一句话结论

**"个人 Life OS / 打卡看板"和"企业 LMS / 培训系统"这两个方向都被人做透了，但把「个人训练 + 团队带教 + 身体训练（八段锦）」放在同一个工作台里的产品，中文互联网和 GitHub 上都没有现成的；最接近的开源实现只有 3 星的 Caliber（工程经理 1:1 看板），其余都是需要拼装的零件。**

换句话说：**轮子有，但都是单个轮子；车架得自己焊。**

再补一层：**架构上最值得抄的不是任何 LMS，而是 3 星的 growth-board——"Markdown/Issue 是唯一数据源，静态页只是投影层"，与你现在的本地 markdown tracker 是同一个思路，只差一个导出脚本。**

## 共性归纳

**大家都做了的（说明是刚需，别自己发明）**
1. 四段闭环：目标/周计划 → 每日执行打卡 → 周复盘 → 下一周滚动（B站教程、Notion 模板、Caliber、one-on-one 全都长这样）。
2. 进度可视化：进度条 / 百分比 / streak / 热力图（飞书案例、obsidian-tracker、beaverhabits）。
3. 资料/知识库与任务双向关联（Notion Resources 库、frappe LMS 课程章节、飞书资料库）。
4. 人-角色分离：学员档案 / 导师 / 管理员三视角（LMS 与带教表格的共同点）。

**普遍缺的（正是可以差异化的地方）**
1. **个人视角与团队视角割裂**：PKM 工具只管自己，LMS 只管别人；没人做"我既是受训者又是带教者"的双面视图。
2. **身体训练缺席**：十几份个人 OS 模板里，运动最多是一行 checkbox（公众号作者自己都承认"缺运动"）；八段锦这类"低强度、每日、可打卡"的训练没有专门模块。
3. **没有"导师点评"闭环**：开源 LMS 有"批改/评分"，但那是作业；带教真正需要的是**每周一句针对性点评**，只有 Word 模板和 Caliber 想到了。
4. **学习时长不可信**：几乎所有方案都在统计"完成率/时长"，没有把"产出物（项目、笔记、分享）"作为主要指标。
5. **中文侧没有开源实现**：企业培训要么买 PlayEdu 商业版，要么用飞书多维表格手工搭，中间没有"轻量、可版本管理、可 Git"的形态。

## 对「合肥团队培训工作台」的 3 条可执行建议

**建议 1：不要部署 LMS，用「Obsidian 单库（个人面）+ 一张飞书多维表格（团队面）」双轨，靠"成员代号 + ISO 周次"对齐。**
理由：PlayEdu/frappe LMS 都要独立账号体系与服务器运维，你面对的是十几人小团队，投入产出不成正比；而带教的真实动作（打卡、点评、周复盘）用文档就能承载。
落地：Obsidian 里只保留 4 类文件 —— `10-成员/<代号>.md`（能力项与目标）、`20-周/<YYYY-Www>.md`（周计划+复盘）、`30-日志/<YYYY-MM-DD>.md`（每日两行：学习 / 运动）、`40-知识库/`。团队面只同步"周状态"四个字段：本周计划完成数、打卡天数、作品链接、导师一句话点评。

**建议 2：把"周"作为唯一节奏，用脚本自动生成周文件，抄 one-on-one 的自动化思路。**
sophshep/one-on-one 的做法是 GitHub Action 每周一自动开 PR 塞一份问题清单，双方往里填，周末合并 —— 这解决了"人不主动写"的根本问题，而且留痕可回溯。你在 Obsidian 侧等价实现即可：每周一 cron/脚本用 Templater 模板生成 `20-周/2026-W45.md`，模板里预置 5 个固定问题（本周要交付什么 / 卡在哪 / 学到什么 / 身体状态 / 下周一件最重要的事），周五只需填答案。
关键：**不要做自定义表单和数据库**，先让 6 周跑通再谈工具升级。

**建议 3：能力档案用"作品集"而不是"课程完成率"，并把运动与学习放进同一张打卡表。**
具体：每人固定 3 个能力维度（例：工程实现 / 方案表达 / 业务理解），月度各打 1–5 分并写一句证据（链接到具体 PR、文档、分享），这就是 Caliber 里唯一值得抄的 "career goal + gap analysis"；同时每日打卡表就两列（学习 30min? / 八段锦或运动?），周末用 obsidian-tracker 出两张热力图并排看 —— 认知负荷与身体负荷同时可见，才能避免"越练越崩"。这也正好补上现有所有模板的最大空缺。
